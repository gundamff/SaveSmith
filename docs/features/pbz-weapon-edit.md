# 需求：影之刃零武器修改（PBZ weapon editing）

状态：**待实现**（对外已于 2026-11-05 承诺「下个版本加入」）
来源：B站评论（BV1m4xp6VEH7，用户「跳舞的栀子花」错过铸魂材料后想继续用某把武器）+

作者确认技术上可行，并且已观察到同类工具支持。

## 已知信息

- 当前 `phantom-blade-zero` 模块已解析的字段（`src/games/phantom-blade-zero/model/`）：
  - `Inventory` / `InventoryInfos` / `consumable`（材料、消耗品、图鉴类）
  - `Records`（战绩、死亡次数）
  - `BossRecord`（BOSS 最佳时间）
  - `PBZGameSystem`、`PBZDeathMeta`、`Player`
- 武器（装备/锻造/持有状态）**不在这批字段里**，目前没有任何界面入口。

## 外部参照

- NexusMods「PBZ Editor - Inventory and Save Editor」（开源，2026-11 上架）：
  摘要称支持按名称/类别/地图检索物品、查看图标、加入背包、修改数量或强化。
  **该页面返回 403，无法核实它是否支持「武器解锁」**；引用前需再确认。
- 因此不能把外部工具当作结构依据，只能作为「可行」的旁证。

## 实现前提（缺一不可）

1. **真实存档样本**：至少两份 PBZ `SaveGame.sav`
   - 一份「未拥有某武器」、一份「已拥有该武器」
   - 用于对比定位武器持有/解锁的相关字段
2. **武器 ID 表来源**：解包数据（`docs/games/phantom-blade-zero` 已记录过的容器格式）或游戏内图鉴导出
3. 字段语义确认：持有标记、数量/强化等级、是否与成就/剧情旗标联动

> 依据本项目既有教训：只凭代码里有没有页签，不能推断存档结构（2026-11-05 已因此误判一次）。

## 风险与设计约束

- **坏档风险**：提前生成「本不该拥有」的武器，可能导致存档校验失败或后续剧情/成就异常。
- 因此实现时必须满足：
  1. 写回前强制自动备份（沿用现有 `write_atomic` + backup 机制）
  2. 对「未解锁 → 已解锁」的写入做二次确认弹窗，文案明确「可能坏档，只能从备份还原」
  3. 默认只允许修改**已拥有**武器的数量/强化等级；新增未拥有武器作为高级选项，默认关闭
  4. 校验：写入后立即回读解析，字段不一致则回滚并报错

## 验收标准

- `npm test` 覆盖：已拥有武器改数量、未拥有武器解锁（含回滚路径）
- 手工验证：真实存档改一把已拥有武器 → 进游戏确认生效；改一把未拥有武器 → 记录能否进游戏
- 文档：`README` 与 CHANGELOG 写明风险与回滚方式
