# 社区反馈台账

把 B 站评论区、Nexus Mods 帖子里的**功能需求**和**bug 线索**落到仓库里，避免只存在聊天记录和状态文件里。

## 来源与写入时机

| 来源 | 采集方式 | 写入时机 |
|---|---|---|
| B 站评论区 | `bili_patrol.py` 巡检（无人机每 2 小时，09:37–21:37） | 已按模板回复后立即登记 |
| Nexus Mods 帖子 | `nexus_watch.py`（只读监控） | 转向空月确认后登记 |
| 私信 / 群聊 | 人工 | 发现后登记 |

## 文件

- `bugs.md` —— bug 线索，一行一条，带用户、视频/帖子、版本、复现信息、状态
- `features.md` —— 功能需求，一行一条，带来源、状态
- `quarantine-log.md` —— Nexus 隔离与申诉记录（时间线，含工单号与结果）

## 状态取值

`new` 待人工判断 → `confirmed` 已复现/已定位 → `fixed` 已在某版本修复 → `rejected` 不修（写原因）→ `waiting-user` 等对方回信息

## 规则

1. 对外回复过的，必须有一条对应记录，`reply_ref` 填回复的 rpid 或帖子链接。
2. 没有复现依据的不写"已修"，只写"待复核"。
3. 版本号写具体（`0.17.10`），不写"最新版"。
4. 涉及用户隐私/网盘链接的，不把链接写进仓库（只写"用户已提供存档，存于 local-archive"）。
